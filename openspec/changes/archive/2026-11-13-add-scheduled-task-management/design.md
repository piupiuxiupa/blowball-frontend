## Context

前端是 React 19 + TanStack Query 的三面板 SPA。`openapi.yaml` 已包含 1.3.0 定时任务契约，但生成的 `src/lib/openapi.d.ts` 尚未同步，代码中也没有任务管理入口。现有 `AppLayout` 顶栏和 `LLMTokenDialog` 提供可复用的入口与弹窗模式，`useModels`、`useSessions` 已覆盖模型目录和会话选择。

定时任务管理端点属于 `api / all`，后台执行属于 `agent / all`。前端不应因需要查看执行结果而把任务 CRUD 错路由到 Agent base。执行结果已经可以通过会话消息历史和 `useAttachRun` 的会话详情发现机制读取，无需新增定时任务专属 SSE 链路。

后端契约还有几个直接影响界面正确性的约束：PATCH 省略字段表示不变；单次规则消费后只能通过新的未来 `run_at` 重排；暂停/删除不会隐式取消已启动 Turn；列表没有总数；显式 `model/reasoning_effort` 没有 PATCH 清除为缺省值的表示方式。

## Goals / Non-Goals

**Goals:**

- 提供完整、可操作的任务列表、新建、编辑、启停、删除和运行历史界面。
- 正确表达时间、会话、模型、暂停原因和执行状态，而不在前端复制调度器逻辑。
- 后台刷新、轮询和 mutation 不覆盖用户正在编辑的草稿，不制造重复提交。
- 复用现有聊天面板读取执行结果，并保持 API/Agent 角色边界。
- 使用现有依赖和控件完成，保持变更范围可回退。

**Non-Goals:**

- 不实现手动立即运行、自然语言时间、秒级 cron、固定间隔、通知或重试策略配置。
- 不在前端计算 cron 下次槽位、补跑、重叠或会话 busy 策略。
- 不增加任务专属消息流、SSE 消费器、路由、全局 store 或 npm 依赖。
- 不展示契约未提供的调度器启停/健康状态。
- 第一版不为单次 `at` 提供任意 IANA 时区的 wall-time 转换；其输入口径为浏览器时区。

## Decisions

### 1. 顶栏单弹窗，内部切换列表、表单和历史

在 `AppLayout` 顶栏增加“定时任务”按钮，由一个管理弹窗承载任务列表；新建/编辑和运行历史作为弹窗内视图状态切换，而不是嵌套多个模态框。弹窗草稿、选中任务、当前页码和视图均为局部 React state。

```text
顶栏「定时任务」
        │
        ▼
┌────────────── 管理弹窗 ──────────────┐
│ 任务列表 ⇄ 新建 / 编辑表单           │
│     └────→ 运行历史 → 打开关联会话   │
└──────────────────────────────────────┘
```

左侧会话/文件栏宽度有限且已有两个等分区域，再塞入管理表单会持续挤压主工作区；独立路由则会为轻量管理能力引入不必要的导航状态。顶栏弹窗与现有“模型令牌”入口一致，且关闭后即可露出聊天结果。

### 2. 生成类型 + 薄 React Query 数据层，不预建通用 API 框架

先运行既有 `npm run generate-api`，再在 `src/lib/api.ts` 从 `paths`/`components` 导出 `ScheduledTask`、`ScheduledTaskCreate`、`ScheduledTaskPatch`、`ScheduleRule`、列表和运行历史类型。所有任务请求使用 `apiGet/apiPost/apiPatch/apiDelete`，因此自动携带 JWT 并固定走 API base。

新增一个定时任务 hook 模块即可：

- `['scheduled-tasks', offset]`：任务页，limit 固定 20。
- `['scheduled-task-runs', taskId, offset]`：选中任务的运行历史页。
- 创建、修改、启停、删除后按前缀失效任务查询；启停同时失效该任务历史，因为未启动 occurrence 可能被取消。
- 查询仅在弹窗打开且对应视图需要数据时启用；失败保留可见错误和重试入口。

列表已经返回完整 `ScheduledTask`，选中任务直接从当前列表/缓存派生，不额外调用单任务 GET。若后续出现列表摘要化或独立详情页，再增加该查询。

### 3. 原生分页，不虚构总数

两个列表均采用服务端 `limit/offset`。`offset > 0` 时可上一页；当页条目数等于服务端返回的 `limit` 时允许尝试下一页，否则到底。契约没有 `total/has_more`，因此界面不显示伪造的总页数或总条数。

不引入无限列表或通用分页组件。任务与历史各自保存简单页码状态；切换任务时历史页归零，删除当前页最后一条后回到合法页或刷新空页状态。

### 4. 表单草稿与服务器快照分离，PATCH 只发送 dirty 字段

进入新建/编辑视图时初始化本地草稿；后台 refetch 只更新列表和任务快照，不重新初始化正在编辑的草稿。切换任务、主动退出编辑或保存成功后才重建草稿。

保存时以进入编辑时的任务快照为基准构造 PATCH：

- name/prompt、schedule、session、model/effort 各自仅在规范化值发生变化时出现。
- 未修改的 schedule 绝不随名称或指令编辑一起回传，避免已消费 `at` 的过去时间被当作重新排期。
- 启停不经过整张表单，单独发送 `{ enabled: boolean }`，并采用响应中的 `next_run_at/paused_reason`。
- 提交失败保留草稿并显示后端错误；pending 期间禁用重复提交。

采用服务端响应和失效重取，而不是在前端乐观推算下一次槽位、系统暂停原因或 occurrence 状态。

### 5. 时间输入使用浏览器原生能力，后端是唯一调度计算器

`at` 使用 `<input type="datetime-local">`，标签明确显示当前浏览器 IANA 时区。提交前检查非空且晚于当前时间，再用 `Date` 转为带 `Z` 偏移的 RFC3339 `run_at`，`timezone` 保存该浏览器时区。显示绝对时间时统一本地化；未修改既有任务时间时保留原 schedule，不重写其时区。

`cron` 使用原始五字段表达式输入和显式 IANA timezone 文本输入，时区默认取 `Intl.DateTimeFormat().resolvedOptions().timeZone`。前端只做空值和五字段数量等基础校验，不用正则缩窄合法 cron 语法，也不解析宏、DST 或计算下次槽位；完整校验和 `next_run_at` 由后端负责。

该选择避免引入 cron/时区依赖及一套容易出错的 zoned wall-time 转换。若未来要求单次任务按任意时区输入，再单独增加经过 DST 用例验证的转换工具。

### 6. 会话和模型控件复用现有查询，但不复用聊天全局选择状态

会话策略默认 `{mode: 'new'}`；选择 `existing` 时从 `useSessions` 选择当前用户会话并提交 `session_id`。切换为 `new` 时不再发送旧 `session_id`。界面说明新会话模式每次 occurrence 使用独立会话，existing 会话忙时本次可能 `SESSION_BUSY` 跳过。

模型目录来自 `useModels`，但表单值属于当前任务草稿，不能写入聊天输入区的 `ui-store.selectedModel/selectedEffort`。创建时“默认”意味着字段缺省；非 thinking 模型禁止提交非 `none` effort，切换模型时清理不再合法的草稿选择。目录不可用时仍允许编辑其他字段，且不清除原配置。

PATCH 没有 nullable/空串清除语义，所以已有显式 model/effort 的任务不提供无法兑现的“恢复默认”选项，只允许保留或切换到具体值；原本缺省时才保留“默认”选项。此限制在表单旁说明，避免发送必然 400 的请求。

### 7. 运行历史只做事实展示，打开结果复用 ChatPanel

历史记录按计划时间倒序展示，覆盖所有 status/reason 枚举，并显示 `error`、重试/开始/结束等存在的关键字段。非终态为 `pending/preparing/launching/running`；历史存在非终态时进行短间隔轮询，全部终局后停止。任务列表在弹窗打开期间低频刷新以更新下次槽位，关闭弹窗后所有相关轮询停止。

“查看会话”先失效会话列表、关闭弹窗，再调用 `setActiveSession(session_id)`。现有 `ChatPanel` 读取历史，`useAttachRun` 通过会话详情发现仍在运行的 Turn 并 attach；不直接调用定时 run 的 events API，不额外创建流式订阅。会话已删除时保留 occurrence 事实，并沿用现有会话读取错误，不伪造结果。

暂停/删除确认文案明确“已开始的执行不会自动停止”。本版不在历史行另做取消按钮，用户可进入会话使用既有停止能力。

### 8. 状态、错误和可访问性属于主流程

列表、历史、表单均提供 loading、empty、error 和 mutation pending 状态。异步错误保留在当前弹窗内，不静默吞掉；mutation 的 Promise rejection 由事件处理器捕获，避免未处理 rejection。

弹窗沿用现有玻璃样式，同时具备关联标题、明确关闭按钮、Escape 关闭和原生表单 label。危险删除需要确认；请求进行中禁用对应操作，但不锁定无关浏览操作。

## Risks / Trade-offs

- [后台刷新覆盖正在编辑的内容] → 草稿仅在进入编辑时初始化，refetch 只更新服务器快照；增加编辑中刷新回归用例。
- [完整表单 PATCH 意外重排单次任务或触发旧配置校验] → 逐字段 dirty patch，启停独立提交；覆盖已消费 `at` 的名称编辑场景。
- [浏览器时区与既有任务时区不同导致误读] → 显示输入/展示时区，未修改 schedule 不回传；任意时区单次 wall-time 输入明确留待后续。
- [非终态历史不刷新，或关闭弹窗后持续请求] → 仅打开期间启用查询，按非终态状态驱动有界轮询，并在关闭/卸载时停止。
- [运行中任务被误认为已随暂停/删除停止] → 确认与状态文案明确 fence 语义，取消仍走现有会话能力。
- [契约无总数导致分页越界] → 使用返回的 limit/offset 和当页长度，允许空页回退，不显示总页数。
- [模型默认值无法通过 PATCH 清除] → 对已有显式值隐藏“恢复默认”，不猜测空串/null 语义；若后端后续补充清除契约再开放。
- [单弹窗组件随功能增长] → 第一版保持单管理组件和单数据 hook；只有实际出现独立复杂视图时再拆，不预建组件体系。

## Migration Plan

1. 重新生成 OpenAPI 类型并补充导出，先通过 typecheck 确认契约同步。
2. 增加查询/mutation、时间和 dirty-patch 辅助逻辑及小型 Node 回归测试。
3. 接入管理弹窗和顶栏入口，完成列表、表单、历史和会话跳转。
4. 运行现有 Node 测试、`npm run lint`、`npm run build`，再在浏览器验证真实后端及分拆 base 配置。

本变更不修改后端数据，也没有本地持久化迁移。回退时移除顶栏入口和管理代码即可；新增生成类型为增量内容，可保留且不影响旧聊天功能。

## Open Questions

无阻塞问题。模型/思考等级清除和调度器健康状态属于当前契约未提供的能力，按上述明确限制发布；后续若后端扩展契约，再以独立变更补齐。
