## Context

本次 `openapi.yaml` 相对前端上一版契约只增加两组能力：消息请求的 `output_format`，以及普通会话的持久化上下文用量端点和 additive done usage 元数据。现有发送链路已经在 `MessageInput` 捕获正文、图片、模型与思考等级，并由 `useSendMessage` 统一区分立即执行和 queued 接受；因此格式选择应复用该边界，而不是另建发送路径。

现有 `ModelSelector` 在模型目录不超过一项时整体隐藏，不能作为格式选择的唯一宿主。输入区已有“接受后按快照清理、失败保留、跨会话迟到结果不覆盖新草稿”的规则，格式的一次性消费必须遵守同样的竞态约束。

上下文用量方面，全局 React Query 默认关闭聚焦重取，只有会话列表/详情等不触碰文件编辑的查询单独开启。turn 生命周期已经在流自然结束或 attach 回落后统一收尾，并先执行历史 reconcile；这是触发用量刷新的现有位置。后端明确说明 done 与 usage 落库不原子，且快照是最近持久化 turn 的最后 LLM round 观测，不是实时输入估算。

## Goals / Non-Goals

**Goals:**

- 同步生成类型，以最小改动把当轮格式偏好接入立即执行、FIFO 排队和草稿首条消息。
- 格式选择按被接受的提交一次性消费，失败保留，并防止迟到回调清除更新的选择。
- 为普通会话提供准确的上下文预算指示，明确数据所属 run 和测量时点。
- 在打开、聚焦和 turn 收尾后刷新，使用有界的 run-id 核对吸收落库时序。
- 不改动流式分段、消息分组、产物渲染和服务端 FIFO 状态。

**Non-Goals:**

- 不增加“每次回复必须生成文件”的选项，也不承诺模型一定生成所选格式。
- 不增加会话级/用户级格式默认值或持久化偏好。
- 不在等待队列、历史用户消息中伪造格式标记；当前队列和历史契约不返回该值。
- 不根据 token 流、累计 `total_tokens` 或当前模型目录实时推算上下文。
- 不为草稿哨兵或 scheduled-session 查询普通会话的 context-usage 端点。
- 不引入新的组件库、图表库、状态库或浏览器测试框架。

## Decisions

### D1: 重新生成契约类型并沿用双 base 路由

运行 `npm run generate-api` 更新生成文件，在 `src/lib/api.ts` 导出 `SendMessageRequest['output_format']` 相关类型和 `SessionContextUsageResponse` 等命名类型。格式发送继续通过 `apiPostStream` 走 agent base；上下文快照通过 `apiGet` 走 API base。

新增 done usage 字段对当前 `StreamEvent.meta` 的开放形状天然兼容，不增加另一套 SSE usage 解析。备选方案是直接消费 done 的三个数值字段构造 UI 快照，但它缺少完整的 `measured_at/model/remaining_tokens`，又无法消除持久化时序问题，因此只把 GET 作为展示真相源。

### D2: 输入区使用独立的原生格式选择器

在 `ModelSelector` 旁放置紧凑的原生 `<select>`，提供自动、HTML、Word、PowerPoint、PDF、Excel、Markdown，并用 tooltip/辅助文案说明“仅在本轮需要产物时生效”。自动对应省略字段，其余选项直接映射 canonical API 值，不接受 `excel/markdown/ppt/powerpoint` 别名。

独立选择器避免被单模型部署下的模型选择器隐藏条件误伤；原生控件满足键盘和弹层行为，无需复制一套下拉组件。格式只进入请求体的 `output_format`，不得拼入 `content`、附加上下文 XML 或乐观用户消息。

### D3: 用提交快照身份实现一次性消费与竞态保护

输入区把每次有效格式选择表示为带所属会话的本地选择快照；提交时同时捕获该快照与 canonical 格式值。服务端接受（immediate 或 queued）后，仅当当前选择仍是该提交捕获的同一快照时恢复自动。用户在等待接受期间更改格式、切换会话后另作选择，都会产生不同快照，因此旧回调不能清除新选择。请求被拒绝或上传/建会话失败时不执行复位。

备选方案是像模型选择一样连续复用格式，但这会把“当轮偏好”表现成局部默认偏好；无条件在 mutation 成功时清空则存在跨会话竞态，两者均不采用。快照随 mutation variables 传递，但不进入 React Query 消息缓存或 pending-queue 服务端读模型。

### D4: 上下文查询只服务真实普通会话

新增 `['context-usage', sessionId]` 查询，复用统一 `apiGet` queryFn，仅在活动 id 为真实普通会话时启用，并单独设置 `refetchOnWindowFocus:true`。草稿和 scheduled-session 不挂载查询；会话删除时移除对应缓存。

查询失败且没有任何成功数据时指示器隐藏；已有最后成功数据时保留其 run/测量时点语义。收到新的 `available:false` 后不得继续展示此前可用快照的数值，也不得从当前模型目录或更早缓存补齐。

### D5: 用量条采用输入预算口径并保留服务端事实

可用快照的显示占比为 `context_tokens / input_budget_tokens`，视觉进度 clamp 到 `[0,100]`；`max_context_tokens` 只在详细信息中作为硬窗口说明，不作分母。剩余量直接显示 `remaining_tokens`，包括零。模型、run id 和 `measured_at` 放在原生 tooltip/可访问描述中，明确这是最近已持久化 turn 的观测。

指示器不随 streaming token 更新。`available:false`、空会话或无数据时不显示 `0%`、`100% 可用`等伪造结论。轻量文本加进度条即可，无需图表组件。

### D6: turn 收尾按 run id 做有界新鲜度核对

复用 `runOutput` 的统一终局/回落 `finally`，在历史 reconcile 之后异步触发上下文刷新，不阻塞分段清理和下一 run 接管。已知完成 run id 时，最多进行 4 次新鲜读取（`staleTime:0`、关闭 React Query 自动重试），间隔约 300ms；当响应 `available:true` 且 `run_id` 等于刚完成的 run 时提前停止。身份未知时只做一次失效。

读取仍返回上一轮、暂不可用或单次网络失败时进行有限重试；耗尽后保留最后一次服务端结果并停止，不做常驻轮询。每次读取仍写同一 React Query key，UI 只呈现服务端最新响应，不在前端拼接“刚完成 run”的假快照。打开/聚焦查询继续提供后续自然恢复通道。

备选方案是在 done 后仅 invalidate 一次，实现更短但可能长期显示上一轮；固定时间轮询则能掩盖时序，却会在不可用快照上持续制造请求，均不采用。

### D7: 回归放在现有 Node 测试链路

为上下文刷新增加一个小型 Node 测试，用全局 `fetch`  stub 构造“先返回旧 run、再返回目标 run”的响应序列，验证提前收敛和缓存结果；另一个用例覆盖持续旧 run 时的有界停止。格式映射主要是封闭枚举与请求字段透传，通过类型检查和浏览器网络面板验证，不为测试单独抽象请求构造器。

### D8: 历史 Confuse 与当前 Confucius 共用主 Agent 分类

真实历史消息仍携带早期主编排名 `Confuse`。如果只在 `AgentMessage` 精确匹配 `Confucius`，这些行会落入 `SubAgentRow`，表现为只有“已完成”标题而没有正文。新增一个共享 `isConfuciusAgent` 谓词，同时供正文派发与裸主回答间距判断使用，并覆盖当前名、历史名和真正的子 Agent 名。仅兼容名称，不改写持久化消息或流式路由身份。

### D9: 无快照时保留可见状态而不显示数值

`available:false` 是后端对最新行的权威结论。加载尚未返回、空会话和草稿仍可隐藏指示器；但真实普通会话已经明确返回不可用后，头部 SHALL 显示“暂无快照”及原因提示，不显示百分比、进度条或剩余 token。这样用户能区分“功能不存在/请求未回来”和“最新 turn 尚无完整用量”，同时继续遵守不回退旧 run 数值的规则。

## Risks / Trade-offs

- [用户把格式选择理解为生成保证] → 选择器明确“条件性偏好”，普通问答仍可直接文本回复；最终格式验证仍不属于本变更。
- [一次性复位误清后续选择] → 以选择快照身份做条件复位，queued 与 immediate 共用同一接受边界，失败路径不复位。
- [usage 最佳努力写入一直缺失] → 有界重试后停止，展示 run/测量时间，不宣称实时；后续打开或聚焦可自然恢复。
- [最新行不可用导致此前有效数值消失] → 严格遵循后端最新行语义，不回退旧快照，避免展示与最近对话不对应的余量。
- [隐藏会话的终局刷新增加少量请求] → 仅 turn 收尾触发且最多 4 次，无空闲轮询；这比只刷新 active query 更能保证切回会话时数据已收敛。
- [旧后端没有新端点或忽略新字段] → 自动格式省略字段，保持原请求；上下文查询失败不影响聊天。具体格式选择和用量展示需要部署对应新后端。

## Migration Plan

1. 提交已同步的 `openapi.yaml` 并重新生成类型，确认现有 lint/test 基线不变。
2. 先上线格式选择与发送快照，再上线上下文查询、指示器和终局刷新。
3. 浏览器验证立即执行、FIFO、草稿首发、跨会话迟到接受，以及旧 run/新 run 的用量响应序列。
4. 回滚前端即可移除两个入口；服务端消息、队列和 usage 数据无需迁移或清理。旧客户端不传格式仍等价于 `auto`。
